# Izumi Owner Writing API v1

Status: implementation contract for `apps/admin`.

Core owns authentication, content validation, revision control, publication
snapshots, media verification, and AI persistence. Admin communicates only
through `/api/v1`; it never connects to PostgreSQL, Redis, S3 credentials, or
Core's filesystem.

## URL, envelopes, and authentication

The owner client `baseUrl` is the Core origin and optional deployment prefix
before `/api/v1`, for example `https://core.example.com`.

Every successful JSON response uses `{ "data": ... }`. Errors use:

```json
{
  "error": {
    "code": "POST_REVISION_CONFLICT",
    "message": "The post has changed since this working copy was loaded",
    "details": {
      "currentRevision": 4,
      "currentEtag": "W/\"4\""
    },
    "requestId": "..."
  }
}
```

Core returns `x-request-id` on errors. Dates are server-authored ISO 8601 UTC
instants.

- `GET /api/v1/auth/status` is public and reports whether the singleton owner
  exists. Once initialized it also returns the normalized username.
- `POST /api/v1/auth/setup` accepts `{ username, password }` exactly once while
  no Owner exists. The database singleton constraint arbitrates concurrent
  setup attempts.
- `POST /api/v1/auth/login` accepts `{ username, password }`.
- All other owner endpoints require `Authorization: Bearer <token>`.

The username is NFKC-normalized and lowercase. Email is not an authentication
field. Admin clears its stored token and returns to login after a `401`.

## RichDocument and article model

`document` is canonical. It is one Lexical/Haklex serialized editor state.
`content` is compatibility Markdown generated by Core from that document.
Clients must not treat HTML or Markdown as the primary editable value.

```ts
type Post = {
  id: string;
  title: string;
  slug: string;
  document: { root: object };
  content: string;
  contentMigrationState: 'native' | 'pending' | 'failed';
  excerpt: string;
  section: string;
  tags: string[];
  readingMinutes: number;
  status: 'draft' | 'published';
  revision: number;
  hasUnpublishedChanges: boolean;
  publishedAt: string | null;
  createdAt: string;
  updatedAt: string;
};
```

Drafts may start with empty title and generated slug. Publication requires
non-empty title, slug, derived content, excerpt, and section. Slugs match
`^[a-z0-9]+(?:-[a-z0-9]+)*$` and remain globally unique.

Core rejects `poll`, executable `dynamic`, and unknown serialized node types.
Internal post references must target another post with a live publication.
Image/gallery nodes require alternative text. Image, gallery, video, and video
poster URLs must resolve to ready media owned by the current owner.

## Working copy and ETag

The mutable row is a working copy. Every successful create, read, save,
publish, unpublish, restore, or fork response includes:

```http
ETag: W/"<revision>"
```

Changing an existing post requires the ETag originally loaded by the client:

```http
If-Match: W/"4"
```

A stale value returns `412 POST_REVISION_CONFLICT`; a missing value returns
`428 POST_PRECONDITION_REQUIRED`. Admin offers “load server version” and “save
as a new draft” instead of silently overwriting either version.

- `POST /api/v1/posts` creates a working draft.
- `GET /api/v1/posts` supports `page`, `size`, and `status`.
- `GET /api/v1/posts/:id` reads the owner working copy.
- `PATCH /api/v1/posts/:id` saves a non-empty subset and requires `If-Match`.
- `POST /api/v1/posts/references/resolve` resolves up to 100 IDs against live
  publication snapshots for the Admin preview; missing or offline targets are omitted.
- `POST /api/v1/posts/:id/fork-working-copy` preserves a local conflict as a
  new draft and intentionally does not require `If-Match`.

Admin debounces automatic draft saves by 800ms. A response to an older in-flight
save may update the ETag and saved baseline, but must never replace text entered
after that request began.

## Publication snapshots

Publishing creates an immutable snapshot. Public reads use only the live
snapshot and never the working row.

- `POST /api/v1/posts/:id/publish`
- `POST /api/v1/posts/:id/unpublish`
- `POST /api/v1/posts/:id/discard-working-copy`

All three require `If-Match`.

Editing a live article leaves `status: "published"` and sets
`hasUnpublishedChanges: true`; readers continue receiving the prior snapshot.
“Publish update” creates a new snapshot. Unpublishing hides the snapshot while
retaining the working copy and historical first `publishedAt`. Discard restores
the latest publication content into the working copy without deleting history.

The compatibility `status` field remains accepted on create/update for older
clients, but new Admin code uses the explicit commands.

## Media

- `POST /api/v1/media/uploads` accepts one multipart `file` and optional `alt`.
- `GET /api/v1/media/:id` returns the owner-scoped ready asset.
- `GET|PUT /api/v1/storage/settings` reads or replaces the current mode.
- `POST /api/v1/storage/settings/test` writes and removes a probe using the
  saved configuration.

Local storage is the default. S3 or Cloudflare R2 is optional and configured by
the authenticated owner; secret credentials are encrypted and only a masked
value is returned. The browser never receives S3 credentials or an object-store
upload URL.

Core applies streamed byte limits, MIME policy and magic-byte sniffing before
storing the object. Images additionally receive a bounded decode, trusted
width/height calculation, and ThumbHash generation. SVG is rejected. Default
limits are 20 MiB for images and 500 MiB for MP4/WebM. Clients must use the
returned `publicUrl`; they cannot forge dimensions, MIME, ThumbHash, or a
different URL.

## Link cards

`POST /api/v1/link-cards/resolve` accepts `{ url }` and returns bounded title,
description, image URL, and site name metadata. Core permits HTTP(S) only,
rejects private/reserved targets, validates each redirect, pins DNS to the
validated address, limits redirects, response size, and request duration, and
does not execute page JavaScript.

## AI providers and sessions

Provider profiles:

- `GET|POST /api/v1/ai/providers`
- `PATCH|DELETE /api/v1/ai/providers/:id`
- `POST /api/v1/ai/providers/:id/test`

The environment profile has ID `environment`, is read-only, and returns only a
masked key. Owner BYOK secrets are AES-256-GCM encrypted at rest and also return
masked. Owner provider URLs always use public-address validation and an
IP-pinned transport. Production requires HTTPS.

Persistent per-post sessions:

- `GET|POST /api/v1/ai/posts/:postId/sessions`
- `GET|PATCH|DELETE /api/v1/ai/sessions/:id`
- `POST /api/v1/ai/sessions/:id/runs`
- `POST /api/v1/ai/sessions/:id/runs/:runId/cancel`
- `POST /api/v1/ai/sessions/:id/tool-calls`
- `PATCH /api/v1/ai/sessions/:id/tool-decisions/:decisionId`

Runs stream normalized SSE:

```text
event: meta   data: {"runId":"..."}
event: delta  data: {"text":"..."}
event: done   data: {"runId":"...","messageId":"..."}
event: error  data: {"runId":"...","code":"...","message":"..."}
```

Only one run may hold a session lease. Messages and structured tool proposals
persist. Admin records `accepted` before applying a proposed document and
records `rejected` without changing the editor.

## Errors Admin handles explicitly

| Situation                 | Status / code                     | Admin behavior                                |
| ------------------------- | --------------------------------- | --------------------------------------------- |
| Invalid request           | `400 VALIDATION_ERROR`            | Show field feedback.                          |
| Missing publish fields    | `400 POST_PUBLISHING_INCOMPLETE`  | Open settings and highlight fields.           |
| Unsupported rich node     | `400 POST_DOCUMENT_UNPUBLISHABLE` | Keep the working copy and identify the block. |
| Missing image alt         | `400 MEDIA_ALT_REQUIRED`          | Ask for alternative text.                     |
| Media not ready/canonical | `400 MEDIA_NOT_PUBLISHABLE`       | Keep the draft and retry the upload.          |
| Missing/stale ETag        | `428` / `412`                     | Preserve local edits; reload or fork.         |
| Slug conflict             | `409 POST_SLUG_CONFLICT`          | Ask for another slug.                         |
| AI run already active     | `409 AI_RUN_ALREADY_ACTIVE`       | Offer cancel/wait.                            |
| Unauthorized              | `401`                             | Clear the local session.                      |
| Feature not configured    | `503` feature-specific code       | Explain required server configuration.        |

## OpenAPI and SDK

OpenAPI is available at `/api/docs-json` and `/api/docs`. Regenerate the SDK
after contract changes with `pnpm sdk:generate`.

`createIzumiClient().updatePost(id, input, etag?)` accepts an explicit ETag for
new optimistic clients. Omitting it preserves the older two-argument call shape
by reading the latest ETag before the save; this legacy path retains historical
last-write-wins behavior and should not be used by collaborative editors.
