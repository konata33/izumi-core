# Izumi Admin 设计语言

状态：实施基线。所有新增后台页面与组件必须遵循本文；不按页面临时发明视觉规则。

## 1. 来源与边界

Izumi Admin 的唯一视觉母版是 [mx-admin](https://github.com/mx-space/mx-admin)。具体参考其应用壳层、内容页、设置详情和头部操作的实现：

- `apps/admin/src/components/sidebar/index.module.css`
- `apps/admin/src/layouts/content/index.tsx`
- `apps/admin/src/layouts/settings-layout.tsx`
- `apps/admin/src/components/button/header-action-button.tsx`

这是为单一管理员设计的内容后台，不是公开博客、营销站或通用组件展厅。它追求清晰、紧凑和可扫读的工作密度；不引入 shadcn、Linear、Yohaku 或其它产品的视觉语言。

## 2. 不可违背的规则

1. 先选择页面模板，再组合组件；禁止从零拼一张页面。
2. 一个视图带一个主标题；标题、区块标题、字段标签不得重复说明同一件事。
3. 文案只在能改变下一步操作时出现。技术限制和缓存细节在校验失败或用户主动查看前不常驻。
4. 边框用于组织层级，不用于把每个元素都围成卡片；常规内容保持平面。
5. 一张表单只有一个明确的保存入口。文字输入默认显式保存，失败时保留原值并给出反馈。
6. 图标辅助识别，不替代有歧义的操作文字；工具栏中的纯图标操作必须有 `aria-label` 与 `title`。

## 3. 基础令牌

| 层级 | Token | 用途 |
| --- | --- | --- |
| 画布 | `--mx-canvas` | 黑色侧栏与页面外框 |
| 工作区 | `--mx-page` | 内嵌、圆角的后台工作区 |
| 控件 | `--mx-input` | 输入、分段控件、表格内部 |
| 边界 | `--mx-line` / `--mx-line-soft` | 分组与行分隔 |
| 文本 | `--mx-text` / `--mx-muted` / `--mx-subtle` | 主、次、辅助信息 |
| 交互 | `--mx-hover` / `--mx-selected` | 悬停、选中 |
| 语义 | `--mx-danger` / 成功色 | 只用于状态与风险操作 |

- 字体：`Segoe UI`、`Helvetica Neue`、系统无衬线；正文 14px。
- 标题：页面 20px / 600；详情工具栏与区块 14px / 500–600；字段与表格正文 13px；辅助文本 12px。
- 尺度：4、8、12、16、24、32px。行内操作采用 4–8px，页面段落采用 16–32px。
- 圆角：控件 6px，工作区 12px。除移动端抽屉外不扩大圆角。
- 阴影：仅工作区、弹层和移动端抽屉使用；内容区不以阴影分层。

## 4. 页面模板

### 应用壳层

桌面端固定 220px 黑色侧栏，右侧工作区距离画布 8px、圆角 12px。导航切换只更新工作区内容；侧栏和选中标记保持在原位。900px 以下改为底部导航抽屉。

### 内容页

用于列表、查询和常规内容。必须使用 `PageFrame`：64px 顶部工具栏承载标题和图标优先的操作；正文使用统一的 32px 桌面内边距。文章列表属于该模板：桌面端为高密度全宽表格，移动端改为带标题、少量元信息和编辑入口的压缩条目，不能缩小桌面表格。

### 编辑页

使用内容页工具栏，正文是沉浸式 Markdown 画布：标题与 slug 位于画布顶部，正文占据剩余工作区。栏目、摘要、标签和记录进入 336px 的“文章设置”抽屉；抽屉默认收起，发布校验失败时若问题在抽屉字段则自动展开。不要添加预览卡、永久信息侧栏或常驻说明。

### 设置详情页

用于单项低频配置。使用 64px 工具栏与最大 768px 的内容列。每个设置区块由一个图标标题及连续分隔行组成；桌面端行为“左标签 / 右控件”，移动端折叠为纵向。个人资料属于该模板。多项设置才使用“左列表 / 右详情”的主从结构；Izumi 目前只有资料，不虚构左侧列表。

### 身份入口

登录和首次初始化是独立入口：两栏结构、无营销文案、无后台侧栏；只保留身份验证所需字段和当前模式说明。

## 5. 组件契约

| 组件 | 规则 |
| --- | --- |
| 导航项 | 40px 高；图标 20px；账户区 48px；选中使用低对比实底，不使用色条或渐变。 |
| 工具栏操作 | 40px 图标操作用于刷新、保存、设置和发布；带文字按钮只用于内容内的明确确认。 |
| 主按钮 | 页面唯一主要动作为浅色实底；次要操作为透明描边；风险操作用低饱和红色。 |
| 输入 | 13px、6px 圆角；标签常驻，placeholder 只给示例；无意义的帮助文案不显示。 |
| 设置行 | 桌面端两列，行间用细分隔线；一项数据只有一个可见标签。区块图标只作无底色识别，不另起强调色块。 |
| 表格 | 表头 37px，数据行约 60px；标题可点，辅助属性置于第二行；行悬停仅改变底色。 |
| 状态 | 草稿与发布使用小型语义标签；不能用“已连接”“未保存”等无法操作的伪状态。 |
| 反馈 | 保存中、成功、失败均短暂且靠近当前任务；校验错误优先贴近字段。 |
| 空状态 | 只说明无结果与下一步动作，不写产品介绍。 |

## 6. 文案与信息密度

- 页面标题使用业务对象：`文章`、`资料`；不用“文章管理”“基本资料设置”。
- 区块标题只用于真正并列的组：`公开资料` 与 `个人链接`；不要为单一字段再加标题。
- 字段标签使用名词短语：`显示名称`、`个人标题`、`头像`。URL、HTTPS、格式等技术内容仅在示例或错误状态出现。
- 个人链接以平台图标与名称识别；未配置时只给一个轻量的`添加链接`操作，不同时展示“未添加”等状态文案。
- 外部头像地址是实现细节：已配置时只显示缩略图和`更换`操作，点击后才展开 URL 输入；校验失败时自动展开该输入。
- 列表元信息优先使用栏目、状态、日期、slug；不展示 API、同步、缓存等实现细节。
- 所有操作使用动词：`新建文章`、`发布文章`、`保存资料`、`移除`。

## 7. 动效、可访问性与响应式

- 路由内容进入/离开仅使用 180ms 的 opacity + 4px 位移；侧栏选中标记 220ms 滑动。遵从 `prefers-reduced-motion`。
- 不动画宽高、间距或表格布局；悬停最多使用轻微颜色与 1px transform。
- 所有焦点可见；纯图标操作给可访问名称；错误通过 `aria-invalid` 和关联消息表达。
- 900px 以下取消工作区圆角；620px 以下设置行、筛选与页面操作纵向排列。功能不得因窄屏被隐藏。

## 8. 令牌、速查与校验

设计语言不是只供阅读的一份说明。它由三层组成：

1. `src/design/tokens.css` 是颜色、文字角色、阴影、尺寸与动效曲线的唯一数值来源。组件样式只能引用 `--mx-*` 令牌，不直接写色值或字体栈。
2. `src/design/CHEATSHEET.md` 是开发与 Agent 改动 UI 前的最短入口：先选模板、再选原语、最后遵守禁止项。
3. `pnpm check:design` 机械检查令牌是否齐全、页面是否继续使用既定模板，以及业务 CSS 是否绕过令牌。它不会替代浏览器里的密度、键盘和小屏检查。

Yohaku 在这里提供的是设计系统的治理方式——令牌与说明分离、速查约束和可运行校验；它不是 Izumi 的视觉来源。Izumi 的视觉值和组件形态仍只由 mx-admin 决定。

## 9. 实现入口与评审清单

- 页面壳层：`src/components/app-shell.tsx`
- 顶部图标操作：`src/components/header-action.tsx`
- 内容页模板：`src/components/page-frame.tsx`
- 设置原语：`src/components/settings-layout.tsx`
- 令牌：`src/design/tokens.css`
- 设计速查：`src/design/CHEATSHEET.md`
- 视觉原语：`src/style.css`

提交新的 UI 前必须确认：

1. 它属于哪一种页面模板？
2. 是否复用了已有按钮、表格、设置行或反馈原语？
3. 是否有重复标题、静态技术说明或不可操作状态？
4. 桌面、390px 宽度和减少动态效果是否仍可使用？
5. 是否已通过 `pnpm check:design`、`pnpm build` 与 Playwright 验收？
